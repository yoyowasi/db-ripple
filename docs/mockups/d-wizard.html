여기서 실행하는 문장은 복제 DB에서만 돌아갑니다. 원본은 [적용]을 누르기 전까지 바뀌지 않습니다.

경고 · 줄 1삭제하면 연결된 테이블 2곳에서 행이 함께 지워지고 트리거가 발동합니다. 다음 단계에서 범위를 확인합니다.
거부 · 줄 2DROP TABLE 같은 DDL은 미리볼 수 없습니다(거부 규칙 ID 자리). 이 줄을 지우면 진행할 수 있습니다.

입력  DELETE FROM Sales.SalesOrderHeader WHERE SalesOrderID = 43697;status ok · 1.4초

이 문장은 테이블 3개, 4행을 바꿉니다

아래로 내려가며 읽으세요. 먼저 요약, 다음에 번지는 경로, 마지막에 행별 값입니다.

요약

  • 1행은 문장이 직접 지웁니다. Sales.SalesOrderHeader
  • 3행은 연결된 테이블에서 함께 지워집니다(FK 연쇄). SalesOrderDetail 1행, SalesOrderHeaderSalesReason 2행
  • 트리거 1건이 발동하지만 바뀌는 행은 없습니다.
  • 경고 1 트리거 iduSalesOrderDetail 의 귀속은 추론(inferred)입니다. 같은 문장에서 트리거가 여러 개 발동하면 짝짓기를 보장하지 않습니다.
  • 참고 트리거는 발동했지만 변경이 없습니다. 헤더가 먼저 삭제돼 조인이 0행이었습니다(0행 묶음, 점선).

원본에 적용할까요?

적용하면 원본 DB에서 4행이 실제로 삭제됩니다. 취소하면 아무것도 바뀌지 않습니다.

적용 조건

모두 충족돼야 [적용]이 켜집니다. 꺼지면 이유를 모두 보여 줍니다.

적용

  • 미리보기 상태 ok
  • 환경 지문 일치
  • 30분 안(남은 시간 24분)
  • SQL이 미리보기 뒤 바뀌지 않음

원본 DB에 적용합니다. 4행이 실제로 삭제되며 되돌릴 수 없습니다. 적용 직전에 원본이 미리보기 때와 같은지 한 번 더 확인합니다.

꺼진 상태 예시
  • 30분이 지났습니다(PREVIEW_EXPIRED). 미리보기를 다시 실행하세요.
  • 환경 지문이 다릅니다(FINGERPRINT_MISMATCH). 샌드박스를 새로 고치세요.
