**결론: cl·0g3·1g·공개 AW2025의 Q1/Q2/Q3를 각각 3회 완료했다.** Q1 12/12 ready·fingerprint 일치·mismatch 0, 미리보기 18/18 ok·직후 ready, 허용된 실제 apply 9/9 committed·KEYSET_HASH·mismatch 0이다. ## 실행·초기 실패와 수정

요청한 `pwsh -NoProfile -File spikes/sql/sp19_00_run.ps1 -PrecheckOnly`, 기본 전체 실행, `-Sizes 1g -SkipBuild`, `-Sizes aw -SkipBuild`를 실제 실행했다. 성공 실행 종료 코드는 모두 0이다. 기본 빌드는 생략하지 않았다. 크기마다 DB·Host를 정리한 뒤 다음 단계로 진행했다.

1. 환경: 최초 .NET/PowerShell 설치와 SQL 두 대를 새로 준비했다. umask 077의 import probe 0600 거부는 umask 022로 해결했다. 원본 .bak은 rootless UID 매핑으로 Host에서 nobody 소유였고 SQL이 최종 권한 0660을 설정했다. 문서의 default other-read ACL만으로는 읽히지 않았다. Host UID를 지정한 default ACL `setfacl -d -m "u:$(id -u):r--" .data/origin-backup`을 적용하고 실제 COPY_ONLY 백업 파일 읽기로 검증했다. echo probe 통과와 실제 SQL 백업 읽기 성공은 구분했다. 실패한 cl/0g3 Q1 각 1회는 성공 3회 통계에서 제외하고 ignored initial-failed에 보존했다.
2. 스크립트: DockerRootDir의 Test-Path 접근 거부가 terminating error가 됐다. 접근 불가 시 SQL 데이터 볼륨 안 df로 실제 용량을 확인하고 같은 안전 기준을 적용하도록 최소 수정했다. df 실패는 throw로 거부한다. 실제 사전 점검 통과 및 DiskMarginGb=100의 공간 부족 거부를 확인했다.
3. 스크립트: 측정 로그가 없는 실패 경로에서 Read-Table이 null을 반환해 요약 배열 인덱싱이 중단됐다. 빈 배열을 반환하도록 한 줄 수정했다. 누락 결과 회귀의 실패→통과, 단일/다중 행 모양·로컬 df·컨테이너 df 파싱·조회 실패 거부 총 6개를 검증했다. AW 초기 실패 때에도 요약이 정상 생성돼 실패 1건을 기록했다.
4. 환경: AW 첫 시도는 최초 다운로드 파일 0600이 복사되어 SQL RESTORE HEADERONLY가 3201/3013(OS access denied)로 거부됐다. 공개 원본 백업만 0644로 준비해 해결했다. SQL 주버전 오류나 제품 결함이 아니다. 초기 실패 로그/summary는 ignored initial-failed에 분리했다.
