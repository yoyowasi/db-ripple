## 환경 문제(제품 결함 아님)

- 첫 [적용]이 `precondition_failed / EXECUTE_AS_USER_MISSING`("원본에 실행 사용자(dbr_preview_user)가 없습니다. 준비 단계가 필요합니다")로 막혔다. 컨테이너의 `AW_Origin`에 `dbr_preview_user`가 없었다(`restore-aw-origin.ps1`은 복원 때 만드는데, 지금 AW_Origin은 그 단계를 안 거친 상태). 원본은 바뀌지 않았다(화면 "바뀌지 않았습니다(실행 안 함)", 직접 조회로도 행 존재 확인). 화면 메시지가 원인과 조치("준비 단계 필요")를 알려 줘서 오히려 의도한 동작이다.
- 조치: `. .\scripts\env.ps1; .\scripts\restore-aw-origin.ps1 -PreviewUserOnly`로 사용자·스키마 DML 권한만 만들었다(복원 아님, AW DDL 트리거가 `DatabaseLog`에 GRANT 줄을 남김). 이후 [샌드박스 새로 고침]→미리보기→[적용] 재시도로 통과.
- 비밀번호 칸에 같은 값이 두 번 들어간 입력 실수로 18456이 한 번 났다(위 2번). 제품 동작이 아님.

## 관찰(결함 아님, 필요하면 문서·화면 손볼 점)

- 설정 [저장] 뒤 화면은 홈으로 자동 이동하지 않고 "저장했습니다 … 홈으로 이동" 링크를 보여 준다. 계획서·설정 안내문 "저장하면 홈으로 이동해"와 다르다. 관련 추정: web 설정 화면(`SettingsView`).
- 기준선이 없는 첫 홈 화면은 기본 SQL(UPDATE …)로 `/api/analyze`를 부르고 409 또는 503이 콘솔에 오류로 찍힌다(예상 응답이나 콘솔이 지저분해진다).
- 이 확인 중 쓴 PowerShell 판정 스크립트 하나에서 "쿠키만 POST 200"이 한 번 나왔으나, 같은 시험을 curl(쿠키 파일)과 PowerShell WebSession으로 새 세션에서 다시 하면 모두 401이다. 첫 스크립트의 splat 사용 문제로 보고 재현되지 않아 결함으로 보지 않는다(근거 부족으로 완전 배제는 아님). 코드 확인(정적): 상태를 바꾸는 엔드포인트는 모두 `MapGroup("/api")` 아래이고(`DbRippleApi.cs`), `/api`는 쿠키와 `X-DbRipple-Request` 키가 둘 다 맞아야 통과하며(`LaunchSession.GateAsync`), `/api` 밖 대체 경로는 GET·HEAD만 index를 준다(`Program.cs` MapFallbackToFile). 쿠키만으로 상태를 바꾸는 경로는 코드에 없다.
- Host 종료는 Ctrl+C가 아니라 `Stop-Process`로 했다(창 없이 백그라운드로 띄운 탓). Ctrl+C 정상 종료 경로는 이번에 확인하지 않았다.

## 하지 않은 것

- 화면 캡처 파일은 저장하지 않았다(앱 안 브라우저 캡처는 임시 경로에만 남고 비밀값이 보이는 화면도 없었음). logs/home-test/2026-11-16/exe/에는 Host 로그만 있다.
- 사용자 입력창이 아닌 시스템 브라우저 자동 실행(`--no-browser` 없이 실행)은 확인하지 않았다. 실행 주소는 콘솔에서 읽어 앱 안 브라우저로 열었다.
- `docker compose up`(게시본 compose.yaml) 경로, `mkdir import`가 이미 있던 컨테이너 마운트는 확인하지 않았다(기존 컨테이너 사용 지시).
