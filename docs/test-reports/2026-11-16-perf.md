# 2026-11-16 성능 측정: 큰 DELETE(M5 10만 행·DM6)와 SP9

측정만 했고 제품 코드는 고치지 않았다. 브랜치 `test/home-spikes`. 원시 로그는 `logs/home-test/2026-11-16/perf/`(gitignore).

## 결론

- **최종 판정(부하 없는 재측정, 맨 아래 "재측정(부하 없음)" 절): 큰 DELETE는 이전과 같은 수준이다.** M5 10만 행 total p50 99.0초(이전 105.2초), DM6 5만 행 p50 46.9초. 아래 첫 측정의 +30%는 부하 겹침 가능 값이다.

- (첫 측정, 부하 겹침 가능) **큰 DELETE는 개선되지 않았다.** M5 10만 행 CL20 DELETE total p50은 137.1초로 이전 105.2초보다 길다(+30%). 5만 행 DM6는 p50 47.8초로 이전 M5 5만 행 43.4초와 같은 수준이다. 단계는 같은 모양이다(reread·resolve가 대부분).
- 단, 측정 중간에 오케스트레이터가 같은 PC·같은 SQL 컨테이너에서 빌드·DB 복원을 했다(시작 시각 미확인). M5 표본 #3(298.7초)과 DM6 2회째(61.5초)는 부하가 겹친 값일 수 있다. **핵심 값은 부하가 없는 상태에서 다시 재야 한다**(아래 "미확인").
- **SP9 브라우저 렌더는 정식 측정을 못 했다.** 앱 내장 브라우저 창이 숨겨진 상태였고 화면 갱신(rAF)이 멈춰 "전체" 시간이 크기와 무관하게 2~4초로 나왔다. 참고값(dagre 배치 시간만 쓸 만함)만 남겼다.
