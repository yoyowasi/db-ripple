# SP12 — 깊이 신호(TRIGGER_NESTLEVEL과 @@NESTLEVEL)

**상태: 준비됨, 미실행(2026-11-13).** 스크립트는 정적 검토만 했다(ScriptDom TSql170 파싱 오류 0). 결과 칸은 비어 있다.

## 목적

변경 묶음의 depth는 감사 트리거가 남기는 인자 없는 `TRIGGER_NESTLEVEL()`(트리거 스택 수, A7)이다. 프로시저가 중첩되면 이 값이 달라지는지, EXEC 문장 창 안 묶음을 "깊이 1(PROC_DIRECT)"로 두는 공용 계약이 맞는지 확인한다.
- 프로시저 1~3단 중첩 안에서 일어난 DML의 트리거(깊이 1·2·3 사슬)가 직접 DML과 같은 `TRIGGER_NESTLEVEL()` 값을 내는가.
- `@@NESTLEVEL − TRIGGER_NESTLEVEL()`이 프로시저 중첩 수와 같은가(프로시저 깊이를 따로 알 수 있는 신호가 있는가).
- 프로시저 안 DELETE가 FK 연쇄로 자식 트리거(`trg_C_del`)를 발동할 때 깊이가 부모와 같은가(H2 전제, CL01 OO1과 같은 질문을 프로시저 안에서).

연결: 공용 계약 PROC_DIRECT depth 1, CascadeLab CL23의 "깊이 2 트리거 귀속"·CL22의 FK 연쇄 depth.

## 방법

`spikes/sql/sp12_10_run.sql`. 전용 DB `SpikeLab_SP12`. 테이블 P(부모) → C(FK ON DELETE CASCADE) → M. 트리거 `trg_P_upd`(C UPDATE) → `trg_C_upd`(M INSERT) → `trg_M_ins`, `trg_C_del`(FK 연쇄로 발동). 프로시저 `usp_Inner`(P UPDATE), `usp_Outer`(→ Inner), `usp_Outer2`(→ Outer), `usp_Del`(P DELETE). 트리거·프로시저가 `dbo.SigLog`에 `OBJECT_NAME(@@PROCID)`, `@@NESTLEVEL`, `TRIGGER_NESTLEVEL()`, `@@TRANCOUNT`를 쓴다(감사 트리거 대용).

시나리오 S1~S6은 각자 최상위 배치에서 BEGIN TRAN → 문장 → 신호를 테이블 변수로 읽기 → ROLLBACK → `dbo.SigResult`:
S1 직접 UPDATE(기준) / S2 `EXEC usp_Inner`(프로시저 1단) / S3 `EXEC usp_Outer`(2단) / S4 `EXEC usp_Outer2`(3단) / S5 `EXEC usp_Del`(FK 연쇄) / S6 직접 DELETE(FK 연쇄 기준).

## 통과 기준

스크립트 끝 판정 표(H1~H4). **통과 = 네 가설이 PASS이거나, FAIL이면 실측값으로 depth 규칙(공용 계약)을 정정한다.**

| 가설 | 기대 | 깨지면 |
|---|---|---|
| H1 트리거 깊이(`TRIGGER_NESTLEVEL()`)는 프로시저 중첩에 영향받지 않는다 | S1과 S2~S4의 같은 트리거가 같은 값 | 프로시저 안 묶음의 depth를 보정해야 한다(공용 계약 "깊이 1" 수정) |
| H2 `@@NESTLEVEL − TRIGGER_NESTLEVEL()` = 프로시저 중첩 수 | S1 0, S2 1, S3 2, S4 3, S5 1, S6 0 | 프로시저 깊이를 신호로 쓰지 않는다(쓰기 전에 알림) |
| H3 FK 연쇄로 발동한 트리거의 깊이는 프로시저 유무와 같다 | S5와 S6의 `trg_C_del` 값이 같다 | FK 연쇄 depth 규칙(H2 전제)을 프로시저 안에서 따로 정한다 |
| H4 프로시저 자체는 `TRIGGER_NESTLEVEL()`을 올리지 않는다(0) | `usp_*` 행의 trgNest = 0 | 깊이 정의 재검토 |

## 실패 시 볼 곳

`sp12-part2.log`의 첫 결과 표(`SigResult` 전체)에서 시나리오별 `trgNest`·`nestLevel`을 직접 본다. 트리거가 안 불렸으면(행 없음) `nested triggers` 서버 옵션(`SELECT value_in_use FROM sys.configurations WHERE name = N'nested triggers'`)을 확인한다(기본 1).
