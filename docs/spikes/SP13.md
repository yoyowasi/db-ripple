# SP13 — EXEC @rc 래퍼의 반환값·행 수·결과 집합

**상태: 준비됨, 미실행(2026-11-13).** SQL은 정적 검토(ScriptDom 파싱 오류 0), PowerShell 클라이언트는 구문 검사만 했다. 결과 칸은 비어 있다.

## 목적

EXEC 문장 결과(`StatementResult.returnValue`, `resultSetCount`, `rowsAffected = null`)를 어떻게 얻는지 정한다.
- 반환값을 어떻게 받나: (A) 래퍼 배치 `DECLARE @__rc int; EXEC @__rc = proc; SELECT @__rc` 의 마지막 결과 집합, (B) 원문 `EXEC proc`(반환값 못 받음), (C) `CommandType.StoredProcedure` + ReturnValue 매개변수(리더를 다 읽고 닫은 뒤에야 값이 채워짐).
- 프로시저가 RETURN을 안 하면 0인가, 오류(RAISERROR 16 계속 진행 / THROW 중단)로 끝나면 반환값이 어떻게 되는가(`XACT_ABORT ON/OFF`).
- 결과 집합 수를 어떻게 세나(리더 `NextResult` 반복). 래퍼를 쓰면 +1이라 빼야 한다.
- 드라이버 `RecordsAffected`(NOCOUNT OFF/ON)와 T-SQL `@@ROWCOUNT`(EXEC 직후)가 어떤 값인가 → EXEC의 `rowsAffected`를 null로 둔 계약이 맞는가.

## 방법

1. `spikes/sql/sp13_10_setup.sql`: 전용 DB `SpikeLab_SP13`, 프로시저 6개(`p_ret5`, `p_noret`, `p_two_resultsets`, `p_nocount_on`, `p_raiserror_continue`, `p_throw`)를 만들고 T-SQL로 보이는 값(EXEC 직후 `@rc`, `@@ROWCOUNT`)을 낸다.
2. `spikes/sql/sp13_20_client.ps1`: PowerShell 5.1(System.Data.SqlClient)로 프로시저 × 호출 방식 3 × `XACT_ABORT` 2 = 36개를 `BEGIN TRANSACTION` 안에서 실행하고 결과 집합 수, 집합 안 행 수, `RecordsAffected`, ReturnValue, 래퍼의 마지막 집합 값, 오류 번호를 표로 낸다(끝에 ROLLBACK). 연결은 `DBRIPPLE_SQL_CONNECTION`(env.ps1)에서만 읽고 출력하지 않는다.

## 통과 기준

**통과 = 36행이 모두 기록되고 아래 네 질문에 답이 정해지는 것**(추정과 다르면 실측값으로 계약을 정정):

| 질문 | 기대(추정) | 깨지면 |
|---|---|---|
| Q1 래퍼(A)의 마지막 결과 집합이 `RETURN` 값을 정확히 준다(`p_ret5` 5, `p_noret` 0, `p_two_resultsets` 7, `p_nocount_on` 9) | 일치 | 반환값은 (C) ReturnValue 매개변수로 받는다(EXEC 문장을 파싱해 호출해야 함) |
| Q2 ReturnValue(C)는 리더를 닫은 뒤에만 채워진다 | 리더 열린 동안 DBNull/null | 읽는 시점 규칙을 구현에 반영 |
| Q3 결과 집합 수 = SELECT 수(+래퍼 1). `p_two_resultsets` 2(+1) | 일치 | `resultSetCount` 계산식을 정정 |
| Q4 오류로 끝난 프로시저의 반환값은 없다(THROW) / 계속 진행하면 RETURN 값(RAISERROR) | 일치 | 오류 시 `returnValue = null` 규칙 재검토(CL24 정답 `returnValue: null`) |
| (참고) `RecordsAffected`는 NOCOUNT OFF에서 DML 영향 행 합, ON에서 −1 | 일치 | `rowsAffected = null` 계약 유지 여부 재확인 |

## 실패 시 볼 곳

클라이언트가 연결 오류를 내면 `DBRIPPLE_SQL_CONNECTION`을 확인한다(env.ps1을 같은 PowerShell에서 점 소싱했는지). 표의 `errNo`가 비어 있지 않은 행은 의도한 오류(`p_raiserror_continue` 50000, `p_throw` 50000)인지 본다.
