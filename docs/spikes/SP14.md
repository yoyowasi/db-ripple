# SP14 — 실행 사용자 dbr_preview_user와 프로시저(EXECUTE 권한, 동적 SQL, 3부분 이름)

**상태: 준비됨, 미실행(2026-11-13).** 스크립트는 정적 검토만 했다(ScriptDom TSql170 파싱 오류 0). 프로시저 본문(AW)은 첫 결과 집합(모듈 정의)으로 먼저 확인한다. 결과 칸은 비어 있다.

## 목적

[미리보기]는 `EXECUTE AS USER = 'dbr_preview_user'`(DML 전용, WITHOUT LOGIN)로 문장을 실행한다. EXEC를 지원하려면 이 사용자에게 `EXECUTE`를 줘야 하는데 최소 권한을 유지하면서 되는지 본다.
- (참고: 제품은 2026-11-13 보안 검토 뒤 스키마 단위가 아니라 CALLER 프로시저마다 `GRANT EXECUTE ON OBJECT::`를 준다. 이 스파이크는 스키마 단위로 권한 경계를 재고, 제품 방식은 Core DB 테스트로 확인한다.)
- `GRANT EXECUTE ON SCHEMA::HumanResources`만으로 AW `HumanResources.uspUpdateEmployeeHireInfo`가 성공 경로(직원 1)와 FK 위반 경로(없는 직원 → 547 → CATCH ROLLBACK → `dbo.uspLogError`)에서 어떻게 끝나는가. 권한 부여 전에는 229인가.
- 소유권 체인: 정적 참조(권한 없는 `secret` 스키마)는 통과하고, **동적 SQL은 체인이 끊겨 229**가 나는가. 사용자가 DML 권한을 가진 테이블에 대한 동적 SQL은 성공하는가.
- 가장 중 **3부분 이름**(다른 DB) 읽기·쓰기는 916이고 트랜잭션이 doomed가 되는가(SP10 사실 4 재확인, CL25c 거부 근거).

연결: 공용 계약(프로시저 전용 거부 규칙), CascadeLab CL25a(동적 SQL)·CL25c(3부분 이름), 복원 스크립트가 만드는 실행 사용자(`restore-aw-origin.ps1` Q30).

## 방법

1. AW 판 `spikes/sql/sp14_10_aw.sql`(AW_SpikeB 전용 사본에서만; 다른 DB면 THROW): 시나리오 c0(GRANT 전, 229 예상) → GRANT → a(성공) → b(FK 위반). 각각 `SET XACT_ABORT ON; BEGIN TRAN → EXECUTE AS USER → EXEC → (doomed면 ROLLBACK) → REVERT → ROLLBACK`. 값은 변수에 모아 롤백 뒤 `#r`에 옮긴다. 사본에 남는 변경: GRANT 1건(DDL 트리거 로그 `dbo.DatabaseLog`), 시나리오 b의 `dbo.ErrorLog` 1행.
2. 미니 판 `spikes/sql/sp14_20_mini.sql`(`SpikeLab_SP14` + `SpikeLab_SP14_Other`): 프로시저 5개(정적 secret 읽기, 동적 secret 읽기, 동적 dbo 쓰기, 3부분 이름 읽기·쓰기)를 `dbr_preview_user`로 실행.

## 실행 순서

```powershell
# AW 판(AW .bak이 없으면 먼저 .\scripts\fetch-adventureworks.ps1)
.\scripts\restore-aw-origin.ps1 -DbName AW_SpikeB          # 복원 + dbr_preview_user(스키마 DML) 생성
.\scripts\run-sql.ps1 spikes\sql\sp14_10_aw.sql -Database AW_SpikeB -ContinueOnError -Log spikes\logs\sp14-10-aw.log
# 미니 판
.\scripts\run-sql.ps1 spikes\sql\sp14_20_mini.sql -Part 1 -Log spikes\logs\sp14-20-part1.log
.\scripts\run-sql.ps1 spikes\sql\sp14_20_mini.sql -Part 2 -Database SpikeLab_SP14 -ContinueOnError -Log spikes\logs\sp14-20-part2.log

```

## 통과 기준

각 스크립트 끝 판정 표. **통과 = AW 판 H1~H3와 미니 판 H1~H5가 PASS이거나, FAIL이면 실측으로 권한 설계(스키마 단위 EXECUTE 부여 + 동적 SQL·3부분 이름 거부)를 정정하는 것.**

| 판 | 가설 | 기대 | 깨지면 |
|---|---|---|---|
| AW | H1 EXECUTE 권한 없이는 229 | 229 | 사용자에게 이미 EXECUTE가 있었다(복원 스크립트 확인) |
| AW | H2 스키마 EXECUTE 부여로 성공 경로가 dbr_preview_user로 성공(Pay 행 +1, HireDate 변경) | 성공 | 모듈 안 권한(예: `uspLogError`, 형식·함수) 문제 → 추가 권한 목록을 적는다 |
| AW | H3 FK 위반 경로는 266(봉투 1겹)과 `ErrorLog` 1행 | 266, 1행 | CL24 정답과 SP11 결과를 함께 정정 |
| 미니 | H1 정적 참조는 소유권 체인으로 통과 | ok | 체인이 안 이어짐 → 소유자 규칙 재확인(SP10 추정) |
| 미니 | H2 동적 SQL(권한 없는 테이블) 229 | 229 | 동적 SQL 거부 근거가 약해짐 |
| 미니 | H3 동적 SQL(DML 권한 있는 테이블) 성공 | ok | |
| 미니 | H4 3부분 이름 읽기·쓰기 916 | 916 | |
| 미니 | H5 3부분 이름은 트랜잭션을 doomed(XACT_STATE −1)로 만든다 | −1 | 문장만 실패(거부 근거 완화 가능) |

## 실패 시 볼 곳

- AW 판 첫 배치의 THROW 메시지(AW_SpikeB가 아님 / `dbr_preview_user` 없음 / 프로시저 없음).
- `definition_head` 결과 집합: 프로시저 본문이 스크립트 가정(UPDATE Employee, INSERT EmployeePayHistory, CATCH ROLLBACK + uspLogError)과 다르면 매개변수·기대값을 맞춘다.
- `permissions_before/after_grant` 표: EXECUTE 권한이 실제로 부여됐는지.
