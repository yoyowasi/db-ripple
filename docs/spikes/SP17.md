# SP17 — Split 모드 끝까지: 원본 서버(2022, 제한 로그인) → 로컬 Docker 샌드박스(2025)

**상태: 준비됨, 미실행(2026-11-13).** compose `sql-origin` 서비스(profile `origin`)와 스크립트를 만들었고 정적 검토만 했다(SQL은 ScriptDom TSql170 파싱 오류 0, PowerShell은 PS 5.1 파서 오류 0, compose는 YAML 구문만). Docker는 켜지 않았다. 결과 칸은 비어 있다.

## 목적

Split(원본 서버의 백업을 내 PC의 Docker 샌드박스로 가져와 미리보기 → [적용]은 원본에) 경로가 실제 SQL Server 두 대로 끝까지 도는지 본다. 원본은 주버전이 다른 SQL Server 2022 컨테이너이고, 로그인은 `db_backupoperator` + 본인 DML(`db_datareader`·`db_datawriter`)만 가진다.
- 원본에서 COPY_ONLY 백업 → 가져오기 → 로컬 2025로 `RESTORE WITH MOVE` → 기준선(감사 설치·스냅샷)이 성공하는가.
- 미리보기와 [적용]이 되는가(원본 스냅샷 권한이 없으므로 [적용]의 검증 모드는 SP18·SP21과 이어진다).
- **원본에 DDL이 0건**인가(백업 파일과 msdb 백업 기록만 늘어난다).
- 제한 로그인으로 RESTORE·DDL·ALTER DATABASE는 **권한 오류**로 막히는가.
- 인스턴스 이름·정렬·버전 차이(지문 v2)와 같은 PC 오인 방지 검사가 두 컨테이너에서 어떻게 보이는가.

## 준비물과 이름

| 항목 | 값 |
|---|---|
| 원본 모사 컨테이너 | compose 서비스 `sql-origin`(profile `origin`), 컨테이너 `dbripple-sql-origin`, SQL Server 2022 Developer(`ORIGIN_IMAGE_TAG`, 기본 `2022-latest`), 호스트 포트 `127.0.0.1:14334` |
| 원본 백업 폴더 | 컨테이너 `/var/opt/mssql/backup` = 호스트 `.data\origin-backup`(`ORIGIN_BACKUP_DIR`로 바꿀 수 있음). Split의 UNC 공유(`DbRipple:Backup:SharePath`) 대역이다 |
| 가져오기 폴더 | 호스트 `.data\import` = 샌드박스 컨테이너 `/var/opt/mssql/import`(기존) |
| 원본 DB | CascadeLab(+ CascadeLab_RT). 사례 스키마 cl01~cl25를 원본에 만든다(CL21~CL25의 첫 실제 DB 실행이기도 하다) |
| 제한 로그인 | `dbr_origin_user`(비밀번호는 `.env`의 `ORIGIN_SQL_PASSWORD`, 값은 출력하지 않는다) |
| 샌드박스 | 기존 `sql` 컨테이너(2025), DB `CascadeLab_Sandbox`, 스냅샷 `CascadeLab_Sandbox_base` |

백업 폴더를 가져오기 폴더와 **같은 폴더로 두지 않는 이유**: 제품이 UNC 경로의 .bak을 가져오기 폴더로 복사하는데, 같은 폴더면 자기 파일을 자기에게 복사한다. 두 폴더를 나눠야 복사 단계도 실행된다. 같은 폴더 동작이 궁금하면 `ORIGIN_BACKUP_DIR=./.data/import`를 `.env`에 두고 따로 확인한다(선택).

## 실행 순서

저장소 루트, PowerShell 5.1. 모든 명령의 로그는 `logs\home-test\<날짜>\sp17\`로 옮겨 둔다.

**1. `.env`에 원본 값을 더한다**(편집기로, 비밀번호는 직접 입력). `$` 문자는 쓰지 않는다.

```
ORIGIN_SQL_SERVER=127.0.0.1,14334
ORIGIN_SQL_USER=dbr_origin_user
ORIGIN_SQL_PASSWORD=<8자 이상, 대소문자·숫자·기호 3종 이상>
ORIGIN_SQL_TRUST_CERT=true
```

**2. 원본 컨테이너를 켠다.**

```powershell
New-Item -ItemType Directory -Force .data\origin-backup, .data\import | Out-Null
$env:COMPOSE_PROFILES = 'origin'
docker compose up -d sql-origin
do { Start-Sleep -Seconds 5; $h = docker inspect -f '{{.State.Health.Status}}' dbripple-sql-origin; "health: $h" } until ($h -eq 'healthy')
docker compose ps
```

**3. 원본에 CascadeLab을 만든다.**

```powershell
. .\scripts\env.ps1          # .env를 읽는다(ORIGIN_SQL_PASSWORD도 환경 변수가 된다)
$files = @('cascadelab\sql\00-create-databases.sql') + @(Get-ChildItem cascadelab\sql\cl*.sql | Sort-Object Name | ForEach-Object { 'cascadelab\sql\' + $_.Name })
foreach ($f in $files) { .\spikes\sql\sp_container-run.ps1 $f -Service sql-origin -Log ('spikes\logs\sp17-origin-' + [IO.Path]::GetFileNameWithoutExtension($f) + '.log') }
```

**4. 제한 로그인을 만들고, 원본 지문(전)을 남긴다.**

```powershell
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp17_10_create_limited_login.sql -PasswordFromEnv ORIGIN_SQL_PASSWORD -Log spikes\logs\sp17-10-login.log
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp17_20_origin_fingerprint.sql -Log spikes\logs\sp17-20-before.log
```

**5. 제한 로그인으로 할 수 있는 것·없는 것을 직접 해 본다**(EXECUTE AS LOGIN, 변경은 롤백).

```powershell
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp17_30_limited_probe.sql -ContinueOnError -Log spikes\logs\sp17-30-probe.log
```

**6. Split 연결로 임시 Host를 띄운다**(개발 모드, 포트 5080). 이 PowerShell 창은 Host가 점유한다 → 새 창에서 7~9단계를 한다.

```powershell
. .\scripts\env.ps1 -Split       # 원본·샌드박스 연결 둘을 만든다(비밀번호는 .env 또는 입력, 출력 안 함)
$env:ASPNETCORE_ENVIRONMENT = 'Development'
$env:DbRipple__Mode = 'Split'
$env:DbRipple__OriginDb = 'CascadeLab'
$env:DbRipple__SandboxDb = 'CascadeLab_Sandbox'
$env:DbRipple__SnapshotDb = 'CascadeLab_Sandbox_base'
$env:DbRipple__Backup__ServerPath = '/var/opt/mssql/backup'
$env:DbRipple__Backup__SharePath = (Resolve-Path .data\origin-backup).Path
dotnet run --project src\DbRipple.Host --no-launch-profile
```

**7. 기준선을 만든다**(새 창, 같은 저장소 루트). 상태가 `ready`가 되길 기다린다.

```powershell
$h = @{ 'X-DbRipple-Request' = '1' }
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5080/api/sandbox/refresh -Headers $h
do { Start-Sleep 3; $s = Invoke-RestMethod http://127.0.0.1:5080/api/sandbox; $s.state } until ($s.state -in 'ready','error')
$s | ConvertTo-Json -Depth 6
```
`$s`에서 `mode`(Split), `origin`(서버 이름·버전), `fingerprintMatch`·`fingerprintWarnings`·`fingerprintMismatches`, `baselineAt`을 적는다. 샌드박스 쪽에 복원된 DB와 스냅샷, 소유자를 확인한다.

```powershell
.\scripts\run-sql.ps1 spikes\sql\sp17_25_sandbox_check.sql -Log spikes\logs\sp17-25-sandbox.log
```

**8. 미리보기와 [적용].**

```powershell
$body = @{ sql = 'UPDATE cl07.A SET v = v + 1 WHERE id = 1;' } | ConvertTo-Json
$p = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5080/api/previews -Headers $h -ContentType 'application/json; charset=utf-8' -Body $body
$p.status; $p.netSummary | ConvertTo-Json -Depth 5
# [적용] 1차: 약한 검증 동의 없이(제한 로그인은 원본에 스냅샷을 만들 권한이 없으므로 막혀야 한다)
$a = @{ sqlHash = $p.sqlHash } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri ("http://127.0.0.1:5080/api/previews/" + $p.previewId + "/apply") -Headers $h -ContentType 'application/json' -Body $a | ConvertTo-Json -Depth 6
# [적용] 2차: 약한 검증에 동의
$a2 = @{ sqlHash = $p.sqlHash; allowKeysetVerification = $true } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri ("http://127.0.0.1:5080/api/previews/" + $p.previewId + "/apply") -Headers $h -ContentType 'application/json' -Body $a2 | ConvertTo-Json -Depth 6
```
(2차는 1차에서 미리보기가 소비됐으면 새 미리보기를 만들어 다시 한다. 실행 파일 화면으로 할 때는 [적용]에서 DB 이름 입력과 약한 검증 동의 체크를 거친다.) 응답의 `status`, `verification.mode`, `preconditionFailures`, `limitations`를 적는다.

**9. 원본에 DDL이 0건인지 본다(지문 후)와 원본 값 확인.**

```powershell
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp17_20_origin_fingerprint.sql -Log spikes\logs\sp17-20-after.log
# 전·후 로그의 ddl_ 줄을 비교한다
$b = Select-String -Path spikes\logs\sp17-20-before.log -Pattern '^ddl_'; $a = Select-String -Path spikes\logs\sp17-20-after.log -Pattern '^ddl_'
Compare-Object ($b | ForEach-Object Line) ($a | ForEach-Object Line)
```
Host를 멈추고(Ctrl+C), 원본 컨테이너가 필요 없으면 `docker compose --profile origin stop sql-origin`.

## 통과 기준

| # | 기준 | 확인 위치 |
|---|---|---|
| 1 | 원본(2022)과 샌드박스(2025)가 모두 healthy이고 `.\scripts\env.ps1 -Split`이 두 연결을 만든다 | 2·6단계 |
| 2 | 제한 로그인으로 지문 읽기(`identity`, `fingerprint_*`, `special_filegroups` 등)와 DML(0행), `BACKUP … COPY_ONLY`가 성공한다. **어느 읽기가 실패하는지가 발견**이다(최소 권한에 더 필요한 권한) | 5단계 H1 |
| 3 | 제한 로그인으로 `CREATE TABLE`·`ALTER TABLE`·`CREATE TRIGGER`·`CREATE USER`·`RESTORE`·`ALTER DATABASE`·`CREATE DATABASE`가 **권한 오류**로 실패한다 | 5단계 H2 |
| 4 | `/api/sandbox/refresh` 뒤 `state = ready`, `mode = Split`, `fingerprintMatch`·`fingerprintMismatches`가 설명 가능하다(버전·정렬 차이는 허용 가능한 경고인지 차단인지 적는다) | 7단계 |
| 5 | 샌드박스에 `CascadeLab_Sandbox`와 스냅샷이 있고 소유자가 sa이며 EXECUTE AS OWNER 모듈이 도는 상태다(SP20과 이어짐) | `sp17_25_sandbox_check.sql` |
| 6 | 미리보기가 `ok`이고 변경이 기대와 같다(CL07: A, B 2행, C 2행, D 1행) | 8단계 |
| 7 | [적용] 1차가 약한 검증 동의 없이는 `WEAK_VERIFICATION_NOT_ACCEPTED`(또는 스냅샷 실패 사유)로 막히고, 2차(동의)는 커밋되거나 사유가 분명한 실패다 | 8단계 |
| 8 | **원본 DDL 0**: 전·후 `ddl_` 줄이 모두 같다. 달라지는 것은 `copy_only_backups_CascadeLab`(+1 이상)·`rows_total`(적용했다면)뿐 | 9단계 |

## 실패 시 볼 곳

- 컨테이너가 안 뜨면 `docker compose logs --tail 40 sql-origin`(메모리 부족이면 Docker Desktop 메모리를 늘린다), 비밀번호 복잡도 규칙.
- 백업이 `Operating system error 5`(권한)면 `.data\origin-backup`의 폴더 권한(Docker Desktop 파일 공유)을 확인하거나 `ORIGIN_BACKUP_DIR`을 다른 폴더로 바꾼다.
- `/api/sandbox`의 `state = error`면 Host 창 로그의 마지막 오류 줄(기준선 단계 이름이 앞에 붙는다)과 `sandbox.json`.
- 연결 오류는 `ORIGIN_SQL_*` 값(포트 14334, 제한 로그인 이름)과 `ORIGIN_SQL_TRUST_CERT=true`(2022 자체 서명 인증서).
