# SP11 — 트랜잭션 제어 프로시저와 실행 봉투

**상태: 준비됨, 미실행(2026-11-13).** 스크립트는 정적 검토만 했다(ScriptDom TSql170 파싱 오류 0). 결과 칸은 비어 있다.

## 목적

EXEC 미리보기에서 사용자 프로시저가 `BEGIN/COMMIT/ROLLBACK/SAVE`를 쓸 때 실행 봉투(제품이 연 바깥 트랜잭션 + `XACT_ABORT ON`)가 어떻게 되는지 잰다.
- 프로시저가 균형 잡힌 BEGIN/COMMIT이면 바깥 트랜잭션이 그대로 살아 있어 마지막 ROLLBACK으로 되돌릴 수 있는가.
- 남는 COMMIT은 바깥 트랜잭션을 확정해 롤백 뒤에도 변경이 남는가(거부 사유 REJECT 근거).
- CATCH에서 ROLLBACK한 뒤 로그를 쓰는 프로시저(uspLogError 모양)는 266을 내고, 로그 행이 롤백 뒤 남는가(CL24 정답 근거: failed, 266, isToolFault=false, leavesResidue).
- BEGIN만 하고 끝나는 프로시저, SAVE TRANSACTION을 쓰는 프로시저의 @@TRANCOUNT·오류·남는 변경.

연결: 공용 계약 "프로시저가 ROLLBACK해 트랜잭션이 없어지면 failed + isToolFault=false", CascadeLab CL23(균형)·CL24(CATCH ROLLBACK)·CL25b(남는 COMMIT 거부).

## 방법

`spikes/sql/sp11_10_run.sql`. 전용 DB `SpikeLab_SP11`. 프로시저 5패턴 × 봉투 3종(자동 커밋 0겹, 바깥 1겹, 바깥 2겹) = 15 시나리오. 항상 `SET XACT_ABORT ON`.

| 패턴 | 프로시저 | 하는 일 |
|---|---|---|
| 균형 | `p_balanced` | BEGIN → UPDATE → COMMIT |
| 남는 COMMIT | `p_extra_commit` | UPDATE → COMMIT(BEGIN 없음) |
| CATCH ROLLBACK + 로그 | `p_catch_rollback_log` | BEGIN → UPDATE(CHECK 위반 547) → CATCH: ROLLBACK, Log INSERT, RETURN −1 |
| BEGIN만 | `p_begin_only` | BEGIN → UPDATE (COMMIT 없음) |
| SAVE | `p_save` | SAVE → UPDATE 2 → ROLLBACK 세이브포인트 → UPDATE 1 |

시나리오 실행기 `run_scenario @proc, @depth`(열린 트랜잭션 0개에서 시작해 0개로 끝난다): T를 시드(1:10, 2:20, 3:30)로 되돌림 → depth만큼 BEGIN → (depth > 0이면 "앞 문장" 모사 UPDATE id 3 +100) → 프로시저 호출 → 오류는 CATCH에서 기록 → 남은 트랜잭션 ROLLBACK → 결과(@@TRANCOUNT, XACT_STATE, 트랜잭션 ID, 오류 번호·심각도, T 내용, Log 행 수)를 `dbo.Result`에 쓴다.

## 통과 기준

스크립트 끝의 판정 표(`H1`~`H6`)가 가설별 PASS/FAIL을 낸다. 예측은 스크립트를 쓴 시점의 추정이므로 FAIL은 결함이 아니라 "추정이 틀렸다 → 실측값을 아래 표에 적고 설계를 고친다"는 뜻이다. **스파이크 통과 = 15 시나리오가 모두 기록되고(`dbo.Result`에 시나리오당 3~4행) 아래 세 가정이 확인되거나 실측으로 정정되는 것.**

| 가설 | 기대 | 깨지면 |
|---|---|---|
| H1 균형 패턴은 모든 봉투에서 오류 없고 @@TRANCOUNT 불변 | 오류 없음 | 균형 프로시저도 막아야 한다(EXEC 지원 범위 축소) |
| H2 균형 패턴은 봉투 1·2겹에서 마지막 ROLLBACK 뒤 변경이 남지 않음 | T가 시드로 돌아옴 | 봉투가 원본을 격리하지 못함 → EXEC 미리보기 중단 판단 |
| H3 남는 COMMIT은 봉투 1겹에서 바깥 트랜잭션을 확정해 변경이 ROLLBACK 뒤에도 남음 | 변경이 남음 | CL25b 거부 근거가 약해짐(그래도 거부는 유지 가능) |
| H4 CATCH ROLLBACK + 로그는 봉투 1겹에서 266, 로그 행이 롤백 뒤 남음 | 266, Log 1행 | CL24 정답(266)을 정정한다 |
| H5 BEGIN만 하는 프로시저는 모든 봉투에서 266 | 266 | 별도 처리 규칙 필요 |
| H6 SAVE는 @@TRANCOUNT를 안 바꾸고 봉투 1겹에서 오류 없음 | 오류 없음 | SAVE 허용 여부 재결정 |

## 실패 시 볼 곳

- 시나리오가 중간에 멈추면 `logs\...\sp11-part2.log`의 첫 오류 줄(50001은 열린 트랜잭션이 남은 것: 이전 시나리오의 CATCH에서 쓰기가 실패한 흔적, 3930은 doomed 트랜잭션에서 쓰기 시도).
- `Result.step = 'caught'` 행의 `errNo`·`sev`·`xstate`가 실측의 핵심이다.
