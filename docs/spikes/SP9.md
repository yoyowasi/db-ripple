# SP9 — 브라우저 렌더 시간(그래프·그리드)

**상태: 측정 전(참고값 1회만 있음, 2026-11-11).** 측정 화면과 측정 코드는 준비됐다. 정식 측정은 브라우저 창이 보이는 상태에서 배포용 빌드로 크기마다 3회 이상 재야 한다. 2026-11-11에 배포용 빌드로 재려 했으나 브라우저 창이 숨겨진 상태라 화면 갱신이 늦춰져 시간이 왜곡되므로 기록하지 않았다.

## 목적

설계 §13 SP9와 §10.4 M5의 브라우저 열(첫 그래프·첫 그리드 페이지 렌더)을 채운다. 그래프 노드 수(50·200·500)와 그리드 행 수(1만·5만)에 따라 배치(dagre)와 렌더가 쓸 만한 시간 안에 끝나는지 본다.

## 방법

- 측정 화면: 웹 앱의 `/sp9` 경로(`web/src/views/Sp9View.vue`, 합성 데이터 `web/src/lib/sp9Data.ts`). 서버와 DB가 필요 없다.
  - 그래프: 노드 50·200·500개를 만들어 dagre 배치 시간과 두 프레임 뒤까지의 전체 렌더 시간을 잰다.
  - 그리드: 1만·5만 행의 첫 렌더, 끝까지 스크롤, 정렬(C03 열) 시간을 잰다.
  - 결과 표에 JS 힙(MB)과 User-Agent가 함께 나오고, CSV로 복사할 수 있다.
- 배포용 빌드에서 측정 화면 켜기:

  ```powershell
  cd web
  $env:VITE_ENABLE_SP9 = 'true'; npx vite build; Remove-Item Env:VITE_ENABLE_SP9
  npx vite preview --port 4173    # 브라우저에서 http://localhost:4173/sp9
  ```

- 절차: 다른 탭과 확장 프로그램을 닫고 창을 보이게 둔 채로, 크기마다 3회 이상 재서 중앙값을 m5.csv의 브라우저 열에 옮긴다(week3-plan Q42). PC 사양과 브라우저를 함께 적는다.

### 확인한 사실

- 측정 화면이 배포용 빌드와 개발 서버에서 열리고, 그래프(Vue Flow + dagre)와 그리드(AG Grid Community 36)가 콘솔 오류 없이 그려진다. 그리드는 가상 스크롤로 보이는 행(약 20행)만 DOM에 만든다.

### 추정·미확인

- 위 두 값은 개발 서버(최적화 전 코드)에서 한 번 잰 값이라 배포용 빌드보다 느릴 수 있다(추정).
- 노드 500개와 그리드 5만 행이 쓸 만한 시간 안에 끝나는지는 아직 모른다.

## 증거 범위

브라우저(Claude 데스크톱 앱 내장 Chromium), 합성 데이터. 서버·DB는 쓰지 않았다.
