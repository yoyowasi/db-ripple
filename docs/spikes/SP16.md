# SP16 — @@TRANCOUNT 분기 프로시저: 봉투 안 대 자동 커밋 단독

**상태: 준비됨, 미실행(2026-11-13).** 스크립트는 정적 검토만 했다(ScriptDom TSql170 파싱 오류 0). 결과 칸은 비어 있다.

## 목적

미리보기는 프로시저를 봉투(제품이 연 바깥 트랜잭션) 안에서 실행한다. 사용자가 같은 EXEC를 실제로 실행하면 보통 자동 커밋(바깥 트랜잭션 없음)이다. 프로시저가 `@@TRANCOUNT`를 보고 분기하면 **미리보기가 보여 준 변경이 실제 변경과 달라질 수 있다.**
- "트랜잭션이 없으면 자기 것을 열고 있으면 SAVE" 패턴은 호출 방식과 무관하게 같은 변경인가.
- `@@TRANCOUNT`에 따라 쓰는 값이 다른 프로시저는 단독 대 봉투 1겹·2겹에서 최종 차이가 어떻게 다른가.
- 트랜잭션 밖이면 아무것도 안 하는 프로시저(단독은 변경 없음, 봉투 안은 변경 있음)는 어떻게 보이는가.
→ 결과가 "다르다"면 `@@TRANCOUNT`를 참조하는 프로시저를 경고(WARN_PROC_*) 또는 거부 대상으로 올리는 근거가 된다.

연결: 공용 계약(프로시저 전용 경고·거부 규칙 이름은 be-exec-1), 설계 §10.5(B0 정적 쓰기 대상).

## 방법

`spikes/sql/sp16_10_run.sql`. 전용 DB `SpikeLab_SP16`. 프로시저 3종(`p_own_tran_if_none`, `p_branch_data`, `p_requires_tran`) × 호출 방식 3(0 = 자동 커밋 단독, 1겹, 2겹). 실행기 `run_scenario`는 T를 시드(1:10, 2:20)로 되돌린 뒤 depth만큼 BEGIN → 프로시저 → 프로시저 직후 T 내용(= 미리보기가 보는 최종 차이)과 마지막 ROLLBACK 뒤 T 내용을 `dbo.Result`에 쓴다.

## 통과 기준

마지막 표 `preview_matches_real`(SAME/DIFF)과 `expectation`이 일치한다. **통과 = 3개 프로시저의 SAME/DIFF가 예측과 같거나, 다르면 실측으로 경고 규칙 범위를 정정하는 것.**

| 프로시저 | 예측 | 의미 |
|---|---|---|
| `p_own_tran_if_none` | SAME | 균형 패턴은 미리보기가 실제와 같다 |
| `p_branch_data` | DIFF(+2 대 +1) | `@@TRANCOUNT` 분기는 미리보기 ≠ 실제 → 경고 필요 |
| `p_requires_tran` | DIFF(단독은 변경 없음) | 트랜잭션 의존 프로시저도 같은 경고 |

## 실패 시 볼 곳

`Result.errNo`가 있는 행(예: SAVE가 단독에서 오류, 266). `tcAfter`가 depth와 다르면 프로시저가 카운트를 바꾼 것이다(SP11과 함께 해석).
