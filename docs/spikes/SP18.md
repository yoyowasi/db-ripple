# SP18 — 원본 스냅샷 실패의 오류 번호

**상태: 준비됨, 미실행(2026-11-13).** 스크립트는 정적 검토만 했다(ScriptDom TSql170 파싱 오류 0). 결과 칸은 비어 있다.

## 목적

[적용]의 검증은 원본에 데이터베이스 스냅샷을 만들어 하는 정확 검증이 기본이고, 못 만들면 약한 검증(KEYSET_HASH, 사용자 동의)으로 내려간다. 2026-11-13 결정은 "**예상 밖 스냅샷 오류는 조용히 강등하지 않고 오류로 보인다**"이다. 그러려면 "스냅샷을 만들 수 없는 정상적인 사유(권한 없음, 에디션·경로 제약)"와 "예상 밖 오류"를 오류 번호로 가를 수 있어야 한다. 실제로 어떤 번호가 나는지 잰다.
- 제한 로그인(`CREATE ANY DATABASE` 없음)의 스냅샷 시도는 어떤 번호인가.
- 잘못된 경로(없는 폴더, 쓸 수 없는 폴더)는 어떤 번호인가.
- 이름 충돌(이미 있는 DB 이름), 없는 원본 DB는 어떤 번호인가.
- 권한을 주면(`CREATE ANY DATABASE`) 제한 로그인이 성공하는가(최소 권한 목록에 이 권한을 더하면 정확 검증이 되는가).

연결: SP17(원본 모사 컨테이너·제한 로그인), SP21(약한 검증), 제품의 `OriginSnapshotSuffix`(기본 `_pre`)·`ApplySteps`의 스냅샷 오류 분류.

## 방법

`spikes/sql/sp18_10_snapshot_errors.sql`을 원본 모사 컨테이너(2022)에서 sa로 실행한다. 원본 CascadeLab의 데이터 파일 논리 이름으로 `CREATE DATABASE CascadeLab_sp18 ON (…) AS SNAPSHOT OF CascadeLab`을 만들어 시나리오별로 TRY/CATCH로 오류 번호·심각도·상태·메시지를 기록한다(제한 로그인 시나리오는 `EXECUTE AS LOGIN`).

| 시나리오 | 누구로 | 무엇을 |
|---|---|---|
| s1 | 제한 로그인 | 정상 경로 |
| s2 | sa | 없는 폴더(`/no/such/dir/`) |
| s3 | sa | 정상 경로(기준: 성공해야 함) |
| s4 | sa | 이미 있는 DB 이름(`CascadeLab_RT`)으로 |
| s5 | sa | 없는 원본(`NoSuchDb_sp18`) |
| s6 | sa | 있지도 않은 파일(`bogus_sp18`)을 더해서 |
| s7 | sa | 루트 폴더(`/`, mssql 사용자가 쓸 수 없음) |
| s9 | 제한 로그인 + `CREATE ANY DATABASE` 임시 부여 | 정상 경로(끝에서 반드시 REVOKE) |

성공한 스냅샷은 바로 지운다. 끝의 확인 쿼리가 남은 스냅샷 DB 0개, 남은 임시 권한 0개를 보인다.

## 실행 순서

사전: SP17 2~4단계(원본 컨테이너, CascadeLab 생성, 제한 로그인 생성).

```powershell
$env:COMPOSE_PROFILES = 'origin'
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp18_10_snapshot_errors.sql -ContinueOnError -Log spikes\logs\sp18-10.log
```

## 통과 기준

**통과 = s3(기준)이 성공하고, 나머지 시나리오의 오류 번호가 아래 표에 기록되며, 사유별로 번호가 갈린다(제품이 분류할 수 있다).** 번호가 같은 둘이 있으면(예: 권한 오류와 경로 오류가 같은 번호) 메시지·상태 값으로 가를 방법을 적는다. 예측 H1~H6은 스크립트 끝 판정 표가 낸다(FAIL = 추정과 다름, 결함이 아니라 실측값을 기록한다).

| 가설(추정) | 기대 |
|---|---|
| H1 sa 정상 경로 성공 | 성공 |
| H2 제한 로그인 실패는 권한 오류 | 262(`CREATE DATABASE permission denied in database 'master'`) |
| H3 없는 폴더 | 5133(`Directory lookup for the file … failed`) |
| H4 이름 충돌 | 1801(`Database … already exists`) |
| H5 없는 원본 | 911(`Database … does not exist`) |
| H6 `CREATE ANY DATABASE`를 주면 제한 로그인 성공 | 성공 |

## 실패 시 볼 곳

스크립트 첫 배치의 THROW(CascadeLab·제한 로그인 없음). 결과 표의 `msg` 열이 오류 메시지 앞 200자다. 임시 권한이 남았으면 `REVOKE CREATE ANY DATABASE FROM [dbr_origin_user];`을 sa로 직접 실행한다.
