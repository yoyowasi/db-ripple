# SP10 — 실행 주체(EXECUTE AS USER)와 감사 트리거 권한

- **목적:** 열린 트랜잭션 안에서 EXECUTE AS USER/REVERT를 반복할 수 있는지, DML 권한만 가진 사용자 문맥에서 감사 트리거의 헤더 INSERT와 NEXT VALUE FOR가 소유권 체인으로 성공하는지 본다(A18).
- **결과:** 미실행(2026-11-06 Docker 미설치)
- **증거 범위:** DB(SpikeLab_SP10, SpikeLab_SP10_Other, ROLLBACK). AW_Sandbox 판은 **미완**.

## 방법

`spikes/sql/sp10_10_run.sql` — 1부(master: 두 DB 생성) → `common_audit_store.sql`, `common_hand_audit.sql`(-d SpikeLab_SP10) → `-- PART 2` 이후(끝에서 두 DB 삭제).

- `spk_user`(WITHOUT LOGIN)는 `dbo` 스키마 DML 권한만 가진다. audit 스키마·SEQUENCE 권한은 없다.
- 한 트랜잭션 안에서 5회: 가장 → `UPDATE dbo.T`(감사 트리거 발동) → audit 직접 읽기(실패 예상) → REVERT → 다른 DB 읽기. 마지막에 가장한 채 다른 DB 읽기.
- 음성 대조: `dbo.T2`의 트리거가 `spk_owner` 소유 스키마 `auditx`의 SEQUENCE·테이블에 쓴다.

## 판정(마지막 표의 `verdict`)

| 검사 | 성립(예상) | 깨짐 |
|---|---|---|
| repeat_impersonation | 5회 모두 성공, USER_NAME = spk_user | 가장·REVERT 반복 불가 → 문장마다 연결을 나누는 설계로 바꿈 |
| ownership_chain_header_and_sequence | 감사 헤더 5개(nestLevel 1, tranCount 1) | 0개 또는 오류 229 → §13 '실패하면': 감사 SEQUENCE·테이블 최소 권한(INSERT, UPDATE on SEQUENCE)을 샌드박스에서만 실행 사용자에게 부여 |
| no_direct_audit_permission | 직접 읽기는 229 | 성공하면 권한 설정 오류(실험 무효) |
| other_db_after_revert_ok | REVERT 뒤 다른 DB 읽기 성공 | 실패 → 최종 차이(SP7)를 별도 연결로 |
| other_db_impersonating_fails | 가장 중 다른 DB 읽기 실패(916 예상) | 성공하면 A18 가정과 다름(기록만) |
| negative_control | 229, XACT_STATE −1 예상 | 성공하면 소유권 체인 판정이 무의미(소유자 설정 재확인) |

## 미완

- AW 트리거(iduSalesOrderDetail → TransactionHistory·Person.Person·SalesOrderHeader 갱신)를 DML 전용 사용자로 실행해 dbo 실행 결과와 비교(테이블 변수로 두 실행의 헤더 요약을 담아 대조)하는 AW_Sandbox 스크립트.
