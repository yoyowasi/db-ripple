# SP20 — 고아 dbo와 EXECUTE AS OWNER

**상태: 준비됨, 미실행(2026-11-13).** 스크립트는 정적 검토만 했다(ScriptDom TSql170 파싱 오류 0). 결과 칸은 비어 있다.

## 목적

Split에서는 다른 로그인이 소유한 원본 DB의 백업을 로컬 샌드박스에서 sa로 복원한다. 원본의 소유자 로그인은 로컬에 없다(Windows 로그인이면 SID도 없다).
- 복원 뒤 DB 소유자와 `dbo` 사용자는 무엇이 되는가(원본 SID 유지 = 고아 / 복원한 로그인으로 바뀜).
- `WITH EXECUTE AS OWNER`로 만든 프로시저·트리거가 복원 직후 실행되는가, 고아 dbo면 어떤 오류(15517 등)가 나는가.
- 제품의 복원 뒤 정리(`BaselineSql.AfterRestoreLocal`: `ALTER AUTHORIZATION ON DATABASE::… TO sa`) 전후로 결과가 어떻게 달라지는가.

연결: SP10(실행 주체, 소유권 체인), SP17(Split), `BuildSplitAsync`의 소유자 정리 단계.

## 방법

1. 원본 모사 컨테이너(2022)에서 SQL 로그인 `sp20_owner`(비밀번호는 NEWID로 즉석 생성, 출력 안 함)를 만들고 `SpikeLab_SP20`의 소유자로 한다. `WITH EXECUTE AS OWNER` 프로시저 `usp_as_owner`와 트리거 `trg_T_upd`가 `ORIGINAL_LOGIN()`·`SUSER_SNAME()`·`USER_NAME()`을 `dbo.Whoami`에 남긴다(`sp20_10_origin_prep.sql`).
2. 원본에서 COPY_ONLY 백업(`sp20_20_origin_backup.sql`) → 호스트에서 가져오기 폴더로 복사.
3. 샌드박스(2025) sa로 복원(`sp20_30_sandbox_restore_check.sql`): 소유자·`dbo` 매핑·`usp_as_owner`·트리거 실행(롤백 안) 확인.
4. `ALTER AUTHORIZATION … TO sa` 뒤 같은 확인(`sp20_40_alter_authorization_check.sql`).

## 실행 순서

사전: SP17 2단계(원본 컨테이너 기동). SP17 3~9단계는 필요 없다.

```powershell
$env:COMPOSE_PROFILES = 'origin'
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp20_10_origin_prep.sql   -Service sql-origin -Log spikes\logs\sp20-10-prep.log
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp20_20_origin_backup.sql -Service sql-origin -Log spikes\logs\sp20-20-backup.log
New-Item -ItemType Directory -Force .data\import | Out-Null
Copy-Item .data\origin-backup\sp20_owner_db.bak .data\import\sp20_owner_db.bak -Force
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp20_30_sandbox_restore_check.sql -Service sql -ContinueOnError -Log spikes\logs\sp20-30-restore.log
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp20_40_alter_authorization_check.sql -Service sql -ContinueOnError -Log spikes\logs\sp20-40-after.log
# 정리(양쪽) + 호스트 .bak 삭제
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp20_99_drop.sql -Service sql-origin -Log spikes\logs\sp20-99-origin.log
.\spikes\sql\sp_container-run.ps1 spikes\sql\sp20_99_drop.sql -Service sql -Log spikes\logs\sp20-99-sandbox.log
Remove-Item .data\origin-backup\sp20_owner_db.bak, .data\import\sp20_owner_db.bak -ErrorAction SilentlyContinue
```

## 통과 기준

**통과 = 아래 세 가지가 분명해지는 것.** 어느 쪽이 나와도 결함이 아니라 설계 근거다.

| # | 기준 | 판단 |
|---|---|---|
| 1 | 복원 직후(전) `before_fix_db_owner`가 NULL(고아)인지 sa인지 기록한다 | sa이면 제품의 소유자 정리는 "안전장치"(이미 sa), NULL이면 필수 단계 |
| 2 | 조치(ALTER AUTHORIZATION) 뒤 `after_fix_module_run`에 오류가 없고 `after_fix_whoami` 2행(프로시저·트리거), `suser`가 sa다(판정 H1 PASS) | FAIL이면 소유자 정리만으로 EXECUTE AS OWNER가 해결되지 않음 → 다른 조치 필요 |
| 3 | 조치 전에 모듈 실행이 실패했다면 그 오류 번호(예 15517)를 기록한다 | 미리보기 중 이 오류가 나면 도구 결함이 아니라 DB 소유자 문제임을 안내하는 문구 근거 |
